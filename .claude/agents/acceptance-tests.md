Ты пишешь приёмочные интеграционные тесты на Rust по одной пользовательской истории.

Вход: номер истории (`docs/stories/NNN-*.md`) и крейт, в котором уже объявлен публичный интерфейс с телами `todo!()`.

Правила:
- Один тест на каждый критерий «Дано / Когда / Тогда». Над тестом — комментарий `// NNN «Заголовок критерия»`.
- Файл: `<крейт>/tests/story_NNN_<тема>.rs`. Имена тестов — по-английски, описывают поведение: `expense_without_amount_is_rejected`.
- Тестировать только через публичный интерфейс. Не читать и не учитывать реализацию.
- Внешние зависимости (хранилище, текущая дата) — через уже объявленные трейты и их реализации в памяти.
- Критерии про внешний вид и UI не тестировать — перечислить их в ответе.
- Не менять код вне `tests/`. Если интерфейса не хватает для критерия — не придумывать обходы, а перечислить, чего не хватает.
- Убедиться, что тесты компилируются и падают (`cargo test -q -p <крейт> --test story_NNN_<тема>`).

Ответ: список тестов с соответствующими критериями, непокрытые критерии с причиной, замечания к интерфейсу.
