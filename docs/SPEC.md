# Покупкомер — спецификация продукта

## Что это

Веб-приложение для учёта личных финансов. Пользователь вручную вносит расходы, доходы, переводы и долги по своим счетам в разных валютах и смотрит, сколько тратит по категориям.

Приложение открывается в браузере с компьютера и с телефона.

## Для кого

Для одного человека, который ведёт свои личные финансы. Первый пользователь — автор, но приложение с самого начала делается пригодным для других людей. Общего доступа к данным (семейный бюджет и т. п.) нет: каждый видит только своё.

## Зачем

Существующие приложения (EasyFinance, ZenMoney) не дали автору понятного планирования. В частности, в них не нашлось очевидного способа смотреть траты по подкатегориям, а не только по категориям верхнего уровня.

Долгосрочная цель — планирование на основе истории: по каждой категории (включая подкатегории) видеть среднее за последние 3 полных месяца и сравнивать с ним текущий месяц. Это одновременно план и контроль его выполнения.

Для планирования нужны данные, поэтому первая версия — это удобный ввод операций, настройка категорий и счетов и простые отчёты. Планирование появится, когда накопится несколько месяцев данных.

## Ключевые решения

- **Вход** — через Google-аккаунт. Вошедший пользователь не вводит пароль повторно при каждом открытии; выйти можно в любой момент.
- **Хранение** — в Google Drive пользователя, в скрытой папке приложения (Application Data folder, разрешение `drive.appdata`).
- **Без собственного сервера** — жёсткое требование. Приложение целиком работает в браузере; серверной части нет ни для данных, ни для авторизации.
- **Работа при наличии сети.** Офлайн-режим и установка как приложения — в следующих версиях.
- **Валюты** — у каждого счёта своя валюта. Суммы разных валют не пересчитываются и не складываются: итоги показываются отдельно по каждой валюте.

## Понятия

**Счёт** — место, где лежат деньги: наличные, каждая карта, вклад. Поля: название, валюта, начальный остаток. Тип счёта отдельным полем не хранится, он отражается в названии. Текущий остаток = начальный остаток + все операции по счёту.

**Категория** — статья расходов или доходов. Все категории образуют одно дерево из двух уровней: категория верхнего уровня и её подкатегории (например, «Питание» → «Продукты», «Обеды в городе»). У каждой категории есть признак применимости: «для расходов», «для доходов» или «для расходов и доходов». Новая подкатегория наследует настройки родительской, но их можно изменить. Сумма по категории верхнего уровня включает суммы всех её подкатегорий.

**Контрагент** — человек, которому пользователь дал в долг или у которого взял.

**Операция** — запись о движении денег. Типы:

| Тип | Поля |
|---|---|
| Расход | дата, счёт, категория, сумма, комментарий |
| Доход | дата, счёт, категория, сумма, комментарий |
| Перевод | дата, счёт списания, счёт зачисления, сумма (или две суммы, если валюты счетов разные), комментарий |
| Дать в долг | дата, счёт, контрагент, сумма |
| Взять в долг | дата, счёт, контрагент, сумма |
| Возврат долга | дата, счёт, контрагент, сумма |

Комментарий заполняют редко, поэтому в интерфейсе он малозаметен.

**Порядковый номер внутри дня** — присваивается автоматически каждой операции, чтобы операции одного дня всегда шли в предсказуемом порядке. Вручную не меняется. Новая операция встаёт в конец своего дня. Если у операции меняют дату, в старом дне оставшиеся операции перенумеровываются без пропусков, а в новом дне операция встаёт в конец.

**Долг** — сальдо с контрагентом. Долг можно гасить частями: дал Пете 10 000, он вернул 2 000, 3 000 и 5 000, долг последовательно 8 000, 5 000, 0. Так же в обратную сторону, если должен пользователь. Возврат всегда в той же валюте, что и долг.

## Основные сценарии первой версии

1. **Вход.** Пользователь входит через Google-аккаунт, его данные загружаются из Google Drive.
2. **Начало работы.** Новый пользователь получает стартовый набор категорий и может сразу вносить операции.
3. **Настройка категорий.** Добавить, переименовать, переместить категорию, изменить признак применимости, удалить категорию с переносом её операций в другую категорию.
4. **Счета.** Завести счёт с валютой и начальным остатком, отредактировать его.
5. **Главный экран.** При открытии приложения пользователь видит последние операции (по дням, внутри дня по порядковому номеру) и может очень быстро добавить новую.
6. **Ввод операций.** Расход, доход, перевод (в том числе между счетами в разных валютах), дать в долг, взять в долг, возврат долга.
7. **Исправление.** Отредактировать или удалить любую операцию.
8. **Быстрый доступ.** Остатки по счетам, мои долги, долги мне.
9. **Отчёт по категориям.** Дерево категорий с раскрытием подкатегорий; помесячные расходы или доходы по выбранной категории.

## Что НЕ входит в первую версию

- Планирование и контроль плана (среднее за 3 прошлых месяца, сравнение с текущим месяцем).
- Импорт банковских выписок.
- Базовая валюта, общие итоги в одной валюте, автоматическое получение курсов.
- Офлайн-режим и установка как приложения (PWA).
- Закрытие и удаление счетов с сохранением истории.
- Общий доступ к данным для нескольких людей.
- Фильтры в списке операций.
- Магазины, метки, разбивка одного чека на несколько категорий.
- Вложенность категорий глубже двух уровней.
- Ручное изменение порядка операций внутри дня.

## Открытые вопросы

- Состав стартового набора категорий.
- Можно ли относить операцию к категории верхнего уровня, у которой есть подкатегории, или только к подкатегории.
- Можно ли менять валюту счёта, если по нему уже есть операции.
- Можно ли записать возврат больше остатка долга.
- Как выбирается контрагент: из ранее введённых, с возможностью добавить нового? Можно ли переименовать контрагента?
- За какой период показывать помесячный отчёт по категории.
- Что происходит при одновременной работе с двух устройств.
- Как хранить историю при закрытии счёта (отложено, см. «Что не входит»).
